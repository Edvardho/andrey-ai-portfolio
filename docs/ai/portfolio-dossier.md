# Досье для full-context ассистента

Версия: `2026-09-06.1`. Машинная сборка: `src/lib/portfolio/full-context-dossier.ts`. Не редактируйте её как вторую копию CV: она собирает данные из существующих канонических источников.

## Реестр источников

| Источник | Что считается каноническим |
|---|---|
| `src/data/portfolio-profile.ts` | позиционирование, компании, периоды, публичные контакты и основные метрики |
| `src/data/portfolio-case-facts.ts` | задача, роль, исследование, решения, ограничения, результаты и пробелы шести кейсов |
| `src/data/cases/*.ts` | только существующие артефакты, которые можно открыть в интерфейсе |

Сборка создаёт стабильный ID из scope, поля и текста. Порядок массива не влияет на ID. Точные дубликаты в одном scope удаляются; ни один уникальный факт не обрезается при достижении лимита.

## Классы материала

- `fact` — материал, заявленный автором в портфолио; его можно сообщать как сведения портфолио.
- `interpretation` — авторская оценка (например, hiring signal); ответ на её основе должен быть помечен как вывод.
- `limitation` — риск, незакрытая деталь или явно отсутствующие данные; это обязательная граница для честного ответа.

## Известные границы

- Метрика продукта или команды не равна личному финансовому вкладу дизайнера.
- Скриншоты не анализируются моделью. Она опирается на проверенные текстовые подписи и открывает только уже существующие артефакты.
- В исходных материалах нет подтверждённой ретроспективы «что Андрей сделал бы иначе»; это должно звучать как пробел, а не как догадка ассистента.
- В текущей редакции не найдено неразрешённых противоречий между каноническим сайтом и досье. При появлении конфликта спорную запись нужно исключить из сборки до редакционного решения.

Текущий offline-отчёт: 228 уникальных записей; оценка полного досье — 14 169 токенов. В live-eval фиксируется реальный `inputTokens` провайдера: оценка не выдаётся за фактическое биллинг-измерение.
